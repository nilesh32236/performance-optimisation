What it does

Preload warms eligible cache files, prioritizes critical resources, and can emit conservative next-page hints. Speculation uses the WordPress Speculation Rules API when available. Each layer is bounded and opt-in.

When to use it

Use cache warm-up after Page Cache is stable. Use font, CSS, or LCP preloads when a measured resource blocks the main render. Use prefetch before prerender, and only when target pages are safe to load speculatively.

Safe default

Cache warm-up, sitemap discovery, speculative loading, automatic font discovery, and automatic LCP preload start disabled. When speculation is enabled, the default is prefetch with conservative eagerness. Dynamic WooCommerce routes remain excluded.

How to enable it

  1. Open Preload and confirm Page Cache works for anonymous requests.
  2. Enable one hint at a time, beginning with fonts or the measured LCP image.
  3. For cache warm-up, review excluded URLs before enabling sitemap discovery.
  4. For speculation, keep prefetch and conservative eagerness for the first test.
  5. Save, clear the page, and inspect the response HTML and queue status.

What changes

The plugin schedules bounded warm-up batches, emits resource hints, or adds prefetch/prerender hints. The browser and server may fetch linked assets before the next navigation. Hints compete with the current page for bandwidth, so an unnecessary preload can make LCP worse.

Compatibility considerations

  • WordPress speculation APIs are feature-gated. Older WordPress versions may not emit the rules.
  • Prerender can execute JavaScript on hover and increase origin or analytics load. Test caching and exclusions first.
  • LiteSpeed crawler warm-up is a cache warmer, not synthetic traffic or a load test.
  • WooCommerce account, cart, checkout, and other dynamic routes stay excluded.

How to verify

wp wppo cache preload
wp wppo cache status

Check the HTML for the expected preload, preconnect, or prerender relationship. Watch queue progress and confirm the URL still renders correctly after a warm-up.

How to undo or disable

Turn off the individual hint or speculative mode, save, and clear the affected page cache. Keep the queue excluded from dynamic paths. Pause a stalled queue rather than repeatedly resubmitting it.

Troubleshooting

  • No preload appears: check the toggle, URL list, WordPress capability gate, and exclusions.
  • LCP worsens: remove broad preloads and keep only the measured hero, font, or CSS resource.
  • Preload queue stalls: inspect failed URLs and cache capacity, then use Resume Preload.
  • Prerender causes double requests: switch to prefetch and verify the page is cacheable.

FAQ

Is preloading every asset useful?

No. Preloads compete for bandwidth. Start with the resource the browser needs first.

Should prerender be the default?

No. Prefetch with conservative eagerness is the safer first test.

Does cache warm-up generate traffic for a load test?

No. The crawler is bounded and intended to warm eligible cache variants.
