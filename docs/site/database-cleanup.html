What it does

Database Cleanup removes bounded categories of stale WordPress data and audits autoloaded options. It shows possible work before deletion and uses the same canonical runner in the Dashboard and WP-CLI.

When to use it

Use cleanup after reviewing counts, especially for revisions, auto-drafts, trashed content, expired transients, and orphan metadata. Use the autoloaded-options audit for repeated database growth. Back up the database first.

Safe default

Cleanup and scheduling start disabled. A lock prevents overlapping runs. Unattached media and autoloaded options require an explicit review because a large or unattached row can still be needed.

How to enable it

  1. Open Database and read the counts for each cleanup type.
  2. Run a dry run for the smallest type.
  3. Confirm the retention and age policy.
  4. Run the selected cleanup and review the result count.
  5. Schedule only after the one-time cleanup is correct.

What changes

Selected stale rows or metadata are deleted in bounded batches. Autoloaded-options remediation can apply, revert one option, or revert all after a dry run. Activity entries record aggregate work without logging deleted content.

Compatibility considerations

  • Use a database backup. Cleanup is not a substitute for a backup.
  • Plugins can attach media to posts through custom relationships. Confirm unattached media before deletion.
  • Some autoloaded options are required on every request. Review each candidate instead of deleting by size alone.
  • WooCommerce orders, customers, sessions, and payment records are outside the default cleanup list.

How to verify

wp wppo database counts
wp wppo database cleanup --type=all --dry-run
wp wppo database cleanup --type=expired_transients --yes

Compare counts before and after, inspect the activity log, and confirm the homepage and a WooCommerce flow still work. Purge page or derived caches only when visible content changed.

How to undo or disable

Database deletions cannot be undone from the plugin. Restore from the backup. Autoloaded-options remediation has a revert action. Turn off the schedule after cleanup and keep the backup until the site is verified.

Troubleshooting

  • Unexpected missing media: restore the backup and review the unattached-media policy.
  • Cleanup is locked: wait for the current run or inspect the canonical runner before forcing another run.
  • Site slows after autoload remediation: revert the option and review plugins that load it on every request.
  • Count differs from phpMyAdmin: compare prefix, retention, and dry-run scope before deleting more.

FAQ

Does cleanup delete WooCommerce orders?

No. The default cleanup types do not target orders, customers, sessions, or payment records.

Can I schedule cleanup immediately?

Run a dry run first. Scheduling is for a policy you have already tested.

Is an autoloaded option safe to delete because it is large?

No. Size is a signal, not proof. Review the option owner and use revert.
