How support works

Performance Optimisation is free and open source (GPLv2 or later) with no premium version or upsells. Support is best-effort guidance for the current release: reproduce the problem, share a redacted report, and recover with Undo or a settings backup. There are no guaranteed scores, rankings, or timelines, and no request for credentials, cookies, API keys, or private data — ever.

Before you ask

  1. Start Safe → Test → Review → Advanced only when needed. Enable the Safe preset or one feature at a time and test logged-out before Balanced or Aggressive.
  2. Record a baseline: the failing URL, the exact setting changed, and a logged-out page load.
  3. Run wp wppo verify and keep the output; it reports runtime, filesystem, cache, Redis, LiteSpeed, settings, cron, and uninstall-hygiene findings.
  4. Export your settings (Tools → Export Configuration) so you can re-import them or use Undo Last Settings Change.

Reproduce in five steps

  1. Note WordPress, PHP, server (Apache/nginx/LiteSpeed/OLS), theme, builder, WooCommerce, Redis, and CDN versions.
  2. Change exactly one setting, save, and clear only the affected URL (wp wppo cache clear --page=/sample-page/).
  3. Test logged-out, then logged-in, plus navigation and the main form; test cart and checkout when WooCommerce is active.
  4. Capture response headers and the browser console message for that URL.
  5. Undo or re-import the backup before trying the next change.

What to include (redacted)

  • WordPress/PHP/server versions and hosting context.
  • Exact reproduction URL and click-by-click steps.
  • The single feature changed (preset name or tab + key).
  • Redacted wp wppo system-info and wp wppo verify output.
  • Relevant console or PHP error-log lines with secrets removed.

What to never share

Never include passwords, API keys, Redis credentials, Cloudflare/Bunny tokens, cookies, session IDs, authorization headers, full database dumps, or customer personal data. Exports from this plugin redact secret-shaped values automatically, but always re-check attachments before sending. If a secret was pasted accidentally, rotate it immediately.

Where to ask

  • WordPress.org support forum for public questions.
  • GitHub issues for reproducible bugs with versions and steps.

Upgrades

Back up settings before every major upgrade. Deactivation removes owned cron events, owned drop-ins, and the created WP_CACHE guard; uninstall additionally removes options, activity data, generated cache files, converted-image copies, and post meta. Original Media Library uploads are never deleted by uninstall.
