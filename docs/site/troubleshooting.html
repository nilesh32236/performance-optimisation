Start with a safe diagnosis

Capture the URL, exact setting, action, WordPress/PHP/server versions, and response headers before changing several controls. Run wp wppo verify and keep passwords, API keys, cookies, and authorization headers out of screenshots.

Site looks broken

Disable the most recent transform first: Delay JavaScript, Used CSS, Critical CSS, Combine CSS, then the other asset transforms in reverse order. Save, clear the exact page, and test logged out. If the site still fails, deactivate the plugin through WordPress and inspect the PHP error log and browser console.

CSS is missing or FOUC appears

Turn off Used CSS and Critical CSS one at a time. Keep the full stylesheet fallback. Add builder, dynamic-state, and required selectors to the safelist, regenerate the affected URL, and clear derived cache. If only one builder page fails, keep that page excluded.

JavaScript or the first click fails

Turn off Delay JavaScript, save, clear cache, and test again. Exclude navigation, consent, payment, menu, modal, and builder handles before re-enabling a smaller set. Defer can also affect inline or order-dependent code, so inspect the console and Network panel.

Cache is not clearing

wp wppo cache status
wp wppo cache clear
wp wppo cache clear --page=/sample-page/

Check the owned drop-in, WP_CACHE, directory permissions, cache owner, URL invalidation, and edge purge. A stale LiteSpeed or CDN layer can outlive the origin cache. Use the matching owner’s purge path.

WooCommerce cart or checkout issue

Turn on WooCommerce safe mode, save, clear cache, and run the Woo self-test. Confirm cart, checkout, Store API, and AJAX requests are excluded. Keep payment, session, add-to-cart, and fragment handles out of delay. Restore a backup only if a database cleanup removed data.

Redis cannot connect

wp wppo object-cache status
wp wppo object-cache ping

Check PhpRedis, host, port, TLS, firewall, password, drop-in ownership, and the circuit state. A foreign object-cache drop-in must be removed by its owner. Never paste the Redis password into a ticket.

Critical CSS causes FOUC

Disable Critical CSS, clear the page and derived CSS, and keep the full stylesheet fallback. Re-enable it only after testing the hero, fonts, modal, and builder states. Do not delete every generated artifact first.

Used CSS removes required styles

Add the missing selector or state to the safelist and regenerate the URL. If the failure follows a builder update, keep the page excluded and rerun the health check. Disable Used CSS while investigating if the selector cannot be identified.

WebP or AVIF is not served

wp wppo image status
wp wppo image convert

Check conversion status, generated files, server MIME/Vary rules, and the CDN format policy. On OpenLiteSpeed restart LiteSpeed after rule edits. The original Media Library file remains the fallback.

LiteSpeed headers are absent

Check the detected server, LiteSpeed integration mode, active LiteSpeed Cache, and the rule layer. Nginx does not execute .htaccess. Use generated nginx rules. Keep one page-cache owner.

PageSpeed or RUM data is missing

PageSpeed needs a valid key, public URL, and queued scan. RUM needs the setting enabled and an unobstructed browser beacon. Check ad blockers, consent rules, rate limits, and the Dashboard status without exposing credentials.

How to get help

Include versions, server software, exact reproduction URL, the feature you changed, and redacted wp wppo system-info output. Do not include private data or credentials. Full workflow: Support.

FAQ

Should I clear the entire site first?

No. Clear the affected URL or derived asset first. A full clear is a diagnostic of last resort.

Can I restore a deleted database row?

Not from the cleanup UI. Restore the database backup.

Why does a feature work on staging but fail on production?

Compare server, PHP, theme, builder, CDN, cookies, and cache owner. The compatibility page records the boundary.
