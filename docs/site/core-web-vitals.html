What it does

Core Web Vitals are user experience metrics: LCP measures when the main content appears, INP measures responsiveness, and CLS measures visual stability. Performance Optimisation does not replace these metrics with a proprietary score. Its cache, image, preload, CSS, and JavaScript features target the work behind them.

When to use it

Start when a real page shows slow main content, delayed interaction, or layout shifts. Measure the same URL, device class, and time window before and after each change. A lab score can improve while field data stays flat.

Safe default

  • Page Cache starts enabled for eligible anonymous requests.
  • Native lazy loading and LCP guardrails are enabled.
  • RUM and scheduled PageSpeed scans start disabled.
  • Defer, delay JavaScript, critical CSS, used CSS, CDN edge templates, and speculative prerendering require an explicit opt-in.

How to enable it

There is no global Core Web Vitals switch. Enable the existing feature that matches the metric you measured, then verify the result.

How to improve LCP

  1. Open Performance Audit and inspect the measured LCP element.
  2. If the LCP resource is an image, review Image Optimization → LCP Preload and confirm the hero loads eagerly.
  3. Review Preload → Critical Assets Preloading for the hero, fonts, and above-the-fold CSS.
  4. Check Page Cache headers and make sure the response is not waiting on an uncached server path.
  5. Run one PageSpeed test, then compare real-user data after enough visits accumulate.

How to improve INP

Keep defer and delay JavaScript conservative. Exclude navigation, consent, payment, menu, modal, and builder scripts before moving more files to a delay strategy. Test the first click on touch and desktop. INP can worsen when a small file size hides a long task or a handler that arrives too late.

How to improve CLS

Review image dimensions, font loading, embedded media, and any CSS that reserves space late. Keep lazy-loading exclusions for logos and above-the-fold media. If a layout shifts only after an optimization, disable the narrow transform and keep its cached output until the page is repaired.

What changes

The plugin stores or serves a cached HTML file, rewrites eligible image and asset URLs, emits resource hints, or changes script delivery. It never silently applies a recommendation from the audit.

Compatibility considerations

  • Page builders can render CSS or JavaScript after the initial HTML. Use Elementor-safe mode, builder exclusions, and CSS safelists.
  • WooCommerce cart, checkout, account, Store API, and AJAX paths stay outside shared cache when safe mode applies.
  • LiteSpeed and CDN owners can add another cache layer. Keep one page-cache owner.
  • RUM requires an unobstructed first-party beacon. Privacy tools and network blockers can suppress samples.

How to verify

wp wppo pagespeed scan --url=https://example.com/ --strategy=mobile
wp wppo pagespeed results --url=https://example.com/ --strategy=mobile
wp wppo system-info

Record the LCP element, TTFB, page-cache status, and field sample count. Compare one change at a time. Do not treat a single lab run as proof.

How to undo or disable

Undo the specific feature you enabled. Preset changes keep an automatic restore point. Otherwise turn off the matching switch, save, clear the affected page cache, and reload in a logged-out window. Keep the feature disabled while the site is broken.

Troubleshooting

  • LCP stays slow: check TTFB, the hero URL, cache eligibility, and whether the LCP image loads eagerly.
  • INP worsens: disable delay JavaScript first, then restore one safe exclusion at a time.
  • CLS appears: inspect fonts, images, embeds, and late CSS before changing multiple features.
  • No field data: confirm RUM is enabled and the browser reaches the public beacon.

FAQ

Does the plugin guarantee a green Core Web Vitals score?

No. Hosting, theme code, plugins, content, and visitor networks affect the result. The plugin gives you bounded tools and evidence.

Should I enable every optimization at once?

No. One feature per test makes recovery and attribution clear.

Which metric should I fix first?

Fix the metric that affects the page and audience you measured. LCP work often starts with TTFB and the hero image; INP work starts with long tasks and delayed handlers.
