What it does

Defer lets the browser download and run eligible JavaScript after parsing. Delay holds selected scripts until an interaction, idle period, or viewport trigger. The controls change execution timing, not JavaScript source.

When to use it

Use defer for non-critical scripts that can run after the document parses. Use delay only after checking that a script does not own the first tap, menu, consent, payment, modal, or builder state.

Safe default

Defer and delay start disabled. When you opt in, the safe preset, builder/commerce exclusions, and first-click safety gate remain available. Interaction is the default delay strategy.

How to enable it

  1. Open File Optimization → Scripts.
  2. Enable Defer for a small, known non-critical group first.
  3. Test the first click and keyboard interaction on mobile and desktop.
  4. Enable Delay only for a measured script and choose Interaction, Idle, Viewport, or Priority deliberately.
  5. Keep the exact handles in the exclusion list and save.

What changes

Selected scripts receive a defer attribute or a trigger-based loader. The first interaction, idle timeout, and viewport behavior determine when their handlers attach. A delayed script can consume a tap before its code is ready.

Compatibility considerations

  • Navigation, consent, payment, menu, modal, and builder scripts need early review.
  • WooCommerce safe mode and the commerce preset keep common dynamic paths conservative.
  • Elementor and other builders can add late handles. Keep their safe mode and exclusions on.
  • Per-post Asset Manager overrides can help one template without widening global settings.

How to verify

  1. Clear the page cache after saving.
  2. Load a logged-out page in a private window.
  3. Test the first menu click, search, modal, consent, checkout, and builder interaction.
  4. Inspect the Network panel and browser console.
  5. Compare INP and interaction latency, not only page size.

How to undo or disable

Turn off Defer or Delay, save, clear the page cache, and retest. Keep the failing handle excluded before re-enabling a smaller set. Use the preset restore point when several delay settings changed together.

Troubleshooting

  • First click fails: disable Delay, exclude the handle, and retest.
  • Menu breaks: restore the navigation handle and keep it out of Delay.
  • Checkout breaks: turn WooCommerce safe mode on and restore payment and AJAX exclusions.
  • Builder popup fails: keep Elementor and popup handles excluded.

FAQ

Is defer safer than delay?

Usually. Defer keeps more predictable browser ordering. Delay can affect first interaction.

Why did my script not move?

It may be inline, protected by safe mode, excluded by a preset, or blocked by a per-post override.

Does delay improve INP automatically?

No. It can help a long task, but it can also delay the handler that responds to the first click.
