What it does

LiteSpeed and OpenLiteSpeed support is an explicit coexistence boundary. The plugin can use its own cache, defer to LiteSpeed Cache, run standalone, or resolve the owner automatically. The selected mode is visible in the Dashboard.

When to use it

Use the LiteSpeed mode when the site runs LiteSpeed or OpenLiteSpeed and you need server-level cache headers, purge coordination, TTL variants, or the built-in crawler. Keep one page-cache owner.

Safe default

Automatic mode is the default. It resolves from the detected server and active LiteSpeed Cache plugin. Explicit modes remain available for staging and agencies.

How to enable or configure it

  1. Open the Dashboard and inspect the detected server type.
  2. Review the LiteSpeed integration mode.
  3. Choose auto, wppo, litespeed, or standalone for the page-cache owner.
  4. Save, clear a test URL, and inspect the response headers.
  5. On OpenLiteSpeed, restart LiteSpeed after marked .htaccess changes.

What changes

The adapter emits cache-control, tag, vary, and purge protocol when the LiteSpeed owner is active. Purge synchronization coordinates both plugins behind a lock. TTL and vary groups remain bounded and opt-in.

Compatibility considerations

  • LiteSpeed Enterprise supports the protected ESI path. OpenLiteSpeed does not provide Enterprise ESI, so that bridge remains unavailable there.
  • Do not run two page-cache orchestrators against the same URL.
  • Apache and LiteSpeed can apply marked .htaccess rules. Nginx needs server configuration.
  • Guest, mobile, and WebP/AVIF vary groups must represent a real output difference.

How to verify

curl -sI https://example.com/ | grep -iE 'x-litespeed-cache|x-litespeed-tag|etag|last-modified|vary'
wp wppo cache preload
wp wppo cache status

Check the effective mode, cache owner, headers, purge result, and a real miss followed by a hit. Restart OLS after rule edits before judging the result.

How to undo or disable

Return the mode to auto or standalone, save, and clear a test URL. Keep the competing page-cache module disabled. Do not remove LiteSpeed rules until the origin page works without them.

Troubleshooting

  • Headers absent: check server detection, active LiteSpeed Cache, mode, and the selected rule layer.
  • Old content remains: inspect purge logs, vary groups, and the owner boundary.
  • OpenLiteSpeed ignores rules: restart LiteSpeed after marked file changes.
  • Two caches conflict: choose one page-cache owner and keep the other as a purge bridge only when documented.

FAQ

Does OLS support Enterprise ESI?

No. The plugin exposes the LiteSpeed Enterprise boundary and does not claim that OpenLiteSpeed can provide the same path.

Should I disable the plugin cache when LiteSpeed Cache is active?

Use the explicit LiteSpeed mode. Keep the competing HTML cache and transforms out of the same URL.

Technical reference

The setting is litespeed_integration.mode. The current integration plan and compatibility audit document the header, purge, TTL, vary, crawler, and ESI boundaries.
