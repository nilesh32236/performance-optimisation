What it does

CDN and edge settings control how generated static pages and assets are delivered or purged outside the origin. Performance Optimisation can coordinate purges with Cloudflare, Bunny Edge, and Varnish. Edge HTML Cache templates are available for Cloudflare Workers and Bunny Edge.

When to use it

Use a CDN when your site already has a working edge configuration and you need cache control or faster global delivery. Do not add an edge layer merely because Page Cache is slow. Measure origin TTFB first.

Safe default

CDN purge services and Edge HTML Cache start disabled. External API keys and zone identifiers belong in server-side constants, not in screenshots or exported settings.

How to enable it

  1. Confirm the site works at the origin without a plugin-managed CDN.
  2. Open File Optimization → Network and review the CDN or Edge HTML Cache card.
  3. Choose Cloudflare, Bunny Edge, or both for an edge template. Keep TTL and stale-while-revalidate values conservative.
  4. Define the required server-side token or API key and the zone or pull-zone identifier.
  5. Deploy the generated template, save, and purge one known URL.

What changes

Static HTML can be served or purged at the edge, and generated assets can use edge delivery. CDN purge also runs after a plugin cache clear when the required credentials and identifiers are present. A purge failure does not make the origin page uncached.

How to verify

curl -sI https://example.com/product/ | grep -iE 'cf-cache-status|x-cache|age|vary|etag'
wp wppo cache clear --page=/product/

Confirm a purge reaches the edge, the origin remains healthy, and a second request returns the expected cache status. Test an image URL and a generated asset URL as well as HTML.

How to undo or disable

Disable the edge or purge setting, remove the generated deployment from your edge account, remove server-side credentials when no longer needed, save, and purge the origin. Keep the edge cache disabled until the origin works without it.

Troubleshooting

  • Edge serves old HTML: purge the exact URL, then check the provider response and the origin page.
  • Assets 404: verify generated file paths, wildcard rules, and the provider's origin policy.
  • No purge log: check the zone identifier and server-side credential; never paste them into a ticket.
  • Two layers conflict: keep one page-cache owner and one URL rewrite owner.

FAQ

Does the plugin host my files on a CDN?

No. It generates and coordinates edge configuration. Your CDN account and DNS remain the delivery layer.

Can I use LiteSpeed CDN and the plugin CDN together?

Only after choosing one rewrite owner. Test the combination and avoid two systems generating competing asset URLs.

Why is purge disabled by default?

Purge needs external credentials and can affect a live site. The default keeps activation local and reversible.
