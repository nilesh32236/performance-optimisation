What it does

Redis Object Cache is the optional in-PHP cache layer. It keeps repeated option, post, term, and transient reads out of MySQL when Page Cache cannot serve a complete request.

When to use it

Use Redis when the site has repeated database reads, a reachable Redis service, and PhpRedis available. Test the connection before enabling the drop-in.

Safe default

Redis starts disabled. The plugin refuses to replace a foreign object-cache.php. Passwords stay out of status output and exports. A failed connection falls back safely instead of producing a site fatal.

How to enable it

  1. Open Object Cache and choose Standalone, Sentinel, or Cluster.
  2. Enter the host, port, database, TLS, and authentication settings your infrastructure uses.
  3. Run a connection test before saving credentials.
  4. Enable the object cache, then run wp wppo object-cache status and ping.
  5. Watch hit ratio and circuit state after representative traffic.

What changes

A successful enable writes the owned drop-in and guarded runtime configuration, then flushes stale entries. When Redis is unavailable, the drop-in uses a per-request in-memory fallback and surfaces a safe circuit state.

Compatibility considerations

  • PhpRedis and the selected Redis topology must match the server.
  • A foreign object-cache drop-in blocks ownership.
  • Compression choices depend on the installed PhpRedis extension.
  • Password rotation must reach every web node before changing the server credential.
  • Multisite keys use blog/site isolation where WordPress provides the current blog ID.

How to verify

wp wppo object-cache status
wp wppo object-cache ping
wp wppo object-cache flush

Compare hit/miss, circuit information, and the drop-in marker after real traffic. A reachable Redis server can still show a poor hit ratio when prefixes, serializers, or eviction policy differ from the application.

How to undo or disable

Use the confirmation dialog to disable the object cache. The plugin removes its owned drop-in and flushes plugin-scoped keys. Do not delete an unknown third-party drop-in.

Troubleshooting

  • Cannot connect: check PhpRedis, host, port, TLS, password, firewall, and Redis logs.
  • Foreign drop-in: disable the other cache plugin or remove its drop-in through its own supported process.
  • Poor hit ratio: inspect key prefixes, serializer behavior, eviction, and the circuit state.
  • Password mismatch: rotate every web node and never paste the password into a report.

FAQ

Does Redis replace Page Cache?

No. Page Cache serves complete HTML. Redis reduces database work for requests that reach PHP.

Can I run another Redis plugin?

Only after choosing one owner for object-cache.php. The plugin will not replace a foreign drop-in.

Why did Redis disable itself?

The circuit breaker can suspend the drop-in after repeated connection failures and schedule a recovery probe.

Technical reference

Standalone, Sentinel, and Cluster modes support the current connection policy. Runtime settings belong in the guarded wp-content/wppo-redis-config.php boundary or the documented constant/environment path. Status, exports, and diagnostics redact secret-shaped values.
