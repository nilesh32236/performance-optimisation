What it does

Critical CSS prepares above-the-fold styles for a template. Used CSS builds a page-specific stylesheet from selectors observed in a rendered URL. Both are independent, opt-in pipelines.

When to use it

Use Critical CSS after measuring a render-blocking stylesheet problem. Use Used CSS only when a full stylesheet is demonstrably larger than the page needs and the page has stable HTML states.

Safe default

Both pipelines start disabled. Used CSS keeps a full-stylesheet fallback, user safelist, and builder exclusions. Critical CSS reports generation failures instead of treating them as a successful render.

How to enable it

  1. Open File Optimization and review the CSS settings.
  2. Enable one pipeline on staging.
  3. Use Preview or Dry Run and inspect the generated selectors.
  4. Add dynamic selectors to the safelist before promotion.
  5. Promote, clear the affected page, and test the real page in mobile and desktop.

What changes

Critical CSS writes a bounded template artifact and serves a fallback stylesheet. Used CSS writes a per-URL artifact after checking rendered HTML, queued styles, safelist entries, and freshness.

Compatibility considerations

  • Dynamic classes, JavaScript-created markup, and builder widgets belong in the safelist.
  • Builder cache regeneration can make a previously valid artifact stale.
  • Strict CSP, large stylesheets, and commerce pages can need separate settings.
  • Do not enable Used CSS and Critical CSS as a combined experiment on the first attempt.

How to verify

Inspect the generated artifact, health result, response headers, and rendered page. Test a logged-out page, an editor preview, a form, a modal, and a dynamic state. Re-run after a theme or builder update.

How to undo or disable

Disable the failing pipeline, clear its derived cache, and promote the last-good artifact when the staged controls offer it. Keep the safelist for the next rollout. Do not delete all generated files as the first step.

Troubleshooting

  • Required styles disappear: add the selector to the safelist and regenerate the URL.
  • FOUC appears: disable Critical CSS, clear the page cache, and keep the full stylesheet fallback.
  • Styles break after a builder update: re-run the health check and regenerate the affected template.
  • Used CSS removes dynamic content: add the state selector or disable Used CSS while investigating.

FAQ

Are Used CSS and Critical CSS the same?

No. Used CSS reduces a rendered page's stylesheet; Critical CSS prioritizes above-the-fold styles.

Can I use them together?

You can, but test one pipeline first so a failure has a clear cause.

What is a safelist?

A small set of selectors or handles the optimizer must keep even when it cannot prove they are present in the initial HTML.
