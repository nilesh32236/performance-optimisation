What it does

Monitoring combines explicit PageSpeed scans, first-party Web Vitals (RUM), local telemetry, and read-only suggestions. It helps you decide what to test next. It never applies a code or settings change by itself.

When to use it

Use PageSpeed for a repeatable lab check. Use RUM when you need field evidence from real visitors. Use the Dashboard suggestions to connect a measured issue to an existing control.

Safe default

PageSpeed needs an administrator-provided key and an explicit scan. RUM, scheduled rescans, and server timing start disabled. Suggestions remain read-only. Adaptive tuning and AI-client use remain gated and disabled by default.

How to enable monitoring

  1. Open Performance Audit.
  2. Add a PageSpeed key through the secure Tools or settings surface if you want lab scans.
  3. Choose a public URL and mobile or desktop strategy.
  4. Run a scan and wait for the queued result.
  5. Enable RUM only after you understand the first-party beacon and privacy implications.

What changes

A scan sends the selected public URL and strategy to Google and stores a result for review. RUM posts bounded LCP, INP, and CLS samples to the site's public beacon. The suggestion engine reads evidence and produces a destination label; it does not call an optimization action.

Compatibility considerations

  • PageSpeed results depend on Google's service, quota, and the selected public URL.
  • Ad blockers, privacy tools, consent rules, and rate limits can suppress RUM samples.
  • Core Web Vitals are evaluated at the 75th percentile across real visits, not only at the median.
  • A lab score can improve while field LCP or INP worsens for one template or device class.

How to verify

wp wppo pagespeed scan --url=https://example.com/ --strategy=mobile
wp wppo pagespeed results --url=https://example.com/ --strategy=mobile
wp wppo system-info

Record the URL, device strategy, scan time, LCP element, TTFB, sample count, and the feature you plan to test. Never include an API key, beacon token, cookie, or authorization header in a report.

How to undo or disable

Disable RUM to stop collection. Remove the PageSpeed key through the secure settings surface if the integration is no longer needed. A scan result can remain as history; clear the scheduled scan list and stop auto-rescan if it is not useful.

Troubleshooting

  • PageSpeed never finishes: check the queue, quota, key, and public URL.
  • RUM has no samples: check the toggle, browser blockers, beacon reachability, and rate limits.
  • Suggestions do not match the page: compare the same URL, device class, and time window before acting.
  • A recommendation points to an unexpected tab: use the feature path in the documentation and report the mismatch.

FAQ

Does a PageSpeed score prove a real-user improvement?

No. Use it as a lab signal and compare RUM over a meaningful window.

Does RUM store form values or user IDs?

No. The beacon is designed around bounded metrics and does not store names, emails, form values, user IDs, or cookies with samples.

Can suggestions apply a fix?

No. They navigate you to the existing control so you can review and save it.
