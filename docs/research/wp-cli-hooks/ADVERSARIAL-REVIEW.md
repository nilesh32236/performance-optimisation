## 0. Method & Threshold

| Challenge question | Applied to |
|-------------------|------------|
| **Needed?** Does a real operator/CI run fail without it, or is it ergonomic sugar? | WP-CLI flags, new subcommands, P2/P3 hooks |
| **Redundant?** Does existing `wppo_*`, WP core, or WP-CLI already cover it? | Hook duplicates, generic `updated_option`, `wp option`, `litespeed_*` |
| **Better hook exists?** Is WP core hook more precise/performant? | Lifecycle, `cron_schedules`, `pre_update_option_*`, `script_loader_tag` |
| **Standard way?** Does WP-CLI handbook already define canonical pattern? | `--format`, `--dry-run`, `--yes`, `Formatter` |
| **Complexity / perf?** Does proposal add per-request `apply_filters` on hot path (`template_redirect`, `script_loader_tag` ×40, `wp_head`)? | Hot-path filters, progress bars on 5-item loops |
| **Compat / conflict?** Could default `false` break cache, leak password, collide on multisite, require `switch_to_blog` `restore`? | Multisite, FS, password redaction |
| **Simpler alternative?** One-line `apply_filters` at service vs 3-file `Service` + `Context` + `Hook_Registry`? | Architecture slices |

**Verdict:** `RETAIN` = survive as-is. `MODIFY` = survive with narrowed scope/guard. `REJECT` = drop or defer to docs-only.
