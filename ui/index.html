Three directions. One admin screen.

This is the admin screen for Performance Optimisation, a free WordPress caching and performance plugin, drawn three different ways. All three directions carry the same eight screens, the same fourteen tabs and the same 246 settings, with the same words and the same numbers. Only the shell, the spacing, the type and the colour change. Open them one after another, then pick the one you want to keep.

Before you judge anything

  • It is a static mockup. Nothing here is connected to WordPress, and none of it runs in an admin page.
  • The data is fictional. The site is a made-up coffee roaster; every score, byte count, cache hit rate and image total is invented for the mockup.
  • Nothing is saved and nothing is sent anywhere. This page loads one file — the app's own stylesheet of design tokens.
  • It exists to choose a look, not to ship one. There is no stylesheet, PHP or REST route here to lift into the plugin.

01

The three directions

Same screens, same data, same words — three different answers to “what should a wp-admin page feel like?” Each card is laid out identically on purpose, and the trade-off gets the same box, the same type and the same prominence as the benefits. Read them side by side at 992px and wider, where the trait lines line up into a table.

  1. A

    Native WP

    Longevity. It just looks like WordPress.

    • NavigationHorizontal nav-tab bar. No sidebar to fight.
    • SurfacesGrey #f0f0f1, white postboxes, #c3c4c7 borders.
    • Radius4px on cards, 3px on controls. Square-ish.
    • TypeThe system stack. No Inter, no webfont request.
    • AccentWP blue #2271b1, on actions only.
    • Dark modeInherits wp-admin's own. Nothing to keep in step.
    • GridMedia queries at 640 / 768 / 992 / 1200.
    • To maintainThe smallest of the three. No shadows or gradients.

    Who it suits

    Anyone optimising for the plugin still looking native in five years' time. Best RTL and keyboard behaviour of the three, and the easiest for a contributor who already knows wp-admin.

    Trade-off

    It is the least striking of the three, and that is the point — it will not stand out in a screenshot, a theme-store gallery or a sales pitch. Four-pixel corners and one-pixel borders also read as plain next to a modern theme, so if the plugin is being judged on how it looks in a gallery, this is the direction that loses that comparison.

    Open Native WP app/index.html?theme=native
  2. B

    Premium Command Deck

    The most impressive in a screenshot.

    • NavigationDark sidebar, collapsing to a 64px rail. Drawer at ≤992px.
    • SurfacesWhite cards, gradient stripe per stat, glassy hero.
    • Radius16px cards, 12px controls, 8px small.
    • TypeInter 400–800, headings at 800.
    • Dark modeA full prefers-color-scheme swap.
    • GridContainer queries at 560 / 900, not the window.
    • DepthLayered shadows that lift on hover.
    • To maintainThe largest. Every shadow is a thing to re-check.

    Who it suits

    Anyone who wants the plugin to feel like a paid product, and a sales page or theme-store listing that needs good pictures. It is also the only direction with a dark mode of its own.

    Trade-off

    It is the most to keep in step. A permanently dark sidebar can clash with an admin colour scheme that is not dark, and there are more breakpoints, more queries and more shadow and gradient rules to re-test whenever WordPress changes something. Direction A is roughly half the CSS.

    Open Command Deck app/index.html?theme=deck
  3. C

    Dense Utility

    Power users. Everything in one screen.

    • NavigationNav 220px · content · inspector 320px.
    • Toolbar48px sticky, with search and the ⌘K hint. Press /.
    • Density13px base, 12.5px tables, 8px gaps.
    • NumbersJetBrains Mono, tabular, so columns line up.
    • Surfaces1px #e2e8f0 hairlines. No lift shadows.
    • Labels11px uppercase, widely tracked.
    • ⌘K251 entries: 8 screens, 243 settings.
    • To maintainDenser UI needs more accessibility care.

    Who it suits

    Power users and hosts running large catalogues or whole LiteSpeed fleets, who would rather type a setting name than scroll to it. Everything stays inside one viewport.

    Trade-off

    It is the least welcoming to someone opening the plugin for the first time. Thirteen-pixel type and hairline borders need more accessibility work than a roomy layout does, and the inspector is gone on a laptop, so checking one row's detail costs a click.

    Open Dense Utility app/index.html?theme=utility

02

What is actually in there

All eight screens are built, and the forms are generated from the plugin's own settings inventory: 14 tabs, 246 fields, each with its type, default, allowed values and the rule that decides when it is shown. This is the scope of the mockup, not an aspiration.

  1. 01Page caching

    1 tab · 18 fields · 3 conditional

    • Cache lifetime for pages, posts and products
    • Per-post-type TTL overrides for posts, pages, products
    • CDN purge for Cloudflare or Varnish, with the zone ID and purge URLs
    • Cache for logged-in users, chosen by role
    • Stampede guard and its lock TTL; max size, max files, warn ratio
    • Randomised query guard; WooCommerce safe mode

  2. 02CSS

    1 group · 24 fields

    • Minify, with an exclusion list
    • Combine, with an exclusion list and a FOUC warning
    • Remove unused CSS, with a safelist, a minimum-retained floor and a regression guard
    • Critical CSS with its own size cap, retries, excluded post types and delivery mode
    • Host Google Fonts locally, plus metric fallback and subsetting
    • Minify HTML, strip HTML comments, minify inline CSS and inline JS

  3. 03JavaScript

    1 group · 28 fields · presets

    • Minify and defer, each with an exclusion list
    • Delay with presets — Safe, Balanced, Aggressive — and a custom list
    • Safe mode for the whole page, plus an Elementor safe mode
    • Sandbox preview: idle timeout, idle list, viewport list, priority list
    • Third-party rules with an allowlist and a denylist, and an auto mode
    • Presets for builder, commerce, interaction, consent, analytics, gallery, jQuery

  4. 04Images

    1 tab · 40 fields · 14 conditional

    • Lazy load images, background images, videos and below-the-fold renders
    • WebP and AVIF conversion, AVIF first, smart quality, a skip-small threshold
    • LCP preload: first N images, field override, hero preload, guardrails, minimum samples
    • Responsive limits: max width, excluded widths, max longest edge
    • Placeholders, wrap in picture, auto alt text, discard oversized siblings
    • Server-side or client-side MIME overrides

  5. 05Preloading

    1 tab · 21 fields · 9 conditional

    • Cache warm-up, warm the sitemap, exclude URLs
    • Preconnect to third-party origins you list
    • DNS prefetch for the same job, cheaper
    • Speculative loading: speculation mode, eagerness, prerender list, document rules, RUM gating
    • Preload fonts, auto-discover them, preload CSS by URL
    • Auto LCP preload

  6. 06Database cleanup

    1 tab · 6 fields · 10 item types

    • 10 item types, each with its own risk badge
    • Safe: revisions, expired transients, oEmbed cache, Action Scheduler queue
    • Caution: auto drafts, trashed posts and comments, spam comments, unattached media
    • Review: orphaned post meta — this one needs a decision, so it sits behind a confirmation
    • Schedule, revisions to keep, revision max age, autoload threshold, optimise tables

  7. 07Object cache

    1 tab · 11 fields · 4 conditional

    • Redis in three modes: standalone, Sentinel and Cluster
    • Host and port, used only in standalone mode
    • Node list and master name, used only in Sentinel or Cluster
    • Password, database index
    • Bypass on outage, compression, persistent connections, TLS

  8. 08Advanced

    8 tabs · 46 fields

    • Edge HTML cache and its TTL and bypass rules
    • llms.txt generation
    • AI adaptive suggestions, including refresh CSS on an LCP regression
    • Google PageSpeed API key, held in Tools & Settings
    • Server rules and a CDN mapping repeater — add and remove rows
    • LiteSpeed: vary groups, crawler, ESI; plus WooCommerce, cache ownership
    • Three read-only tabs: OD Integration, Back/Forward Cache, Performance Translations

Counts are from the inventory file itself, not estimated. 65 of the 246 fields are conditional — they are hidden until the setting that governs them is turned on, which is the thing all three directions have to solve well.

03

How to review it

Five things to try in each direction. Spend a couple of minutes per theme on the real screens — the differences only show up once you turn things on and off.

  1. Step one

    The bar in the corner is not part of the plugin

    A floating control pinned to the bottom-right of every screen. It switches theme (A / B / C), forces light or dark, cycles the demo states, and simulates a 1440, 900 or 390px-wide window. The real settings page has no such bar — judge the design as if it were not there. Dark mode is theme B only; A and C inherit whatever wp-admin is doing.

  2. Step two

    Every screen is one click from the sidebar

    Five areas, eight screens: Summary and All diagnostics under Overview, Assets & Scripts and Preload under Speed, Images under Media, Database Cleanup and Object Cache under Data & System, Tools & Settings under Manage. In theme A these are the top nav-tabs instead of a sidebar — the clearest single difference between the directions.

  3. Step three

    Press ⌘K, or Ctrl+K

    The shortcut works in all three themes. Theme C is the one that advertises it, in the 48px toolbar — press / to land in that search box. It indexes 251 entries: 8 screens and 243 settings, searchable by label or by key. The three it leaves out are the enabled switches on the three read-only tabs, which have nothing to configure.

  4. Step four

    Turn things on and off

    The settings really are live. Flip a toggle and the fields it governs appear or disappear — try Critical CSS or Combine CSS on Assets & Scripts. Change anything and an unsaved-changes bar appears at the bottom; Save clears it. On the Network sub-tab the CDN mapping is a repeater you can add rows to and remove rows from.

  5. Step five

    Cycle the demo states before you decide

    The corner bar has a demo control that switches the same screen between Normal, Loading, Error and Partial. These are the states that never show up in a happy-path screenshot, and they are where the three directions differ most: a quiet native notice, a full-width command-deck state, a dense utility empty row. Whichever direction you pick has to survive all four, and this is the quickest way to find out whether it does.

04

Pick one

One line each. If two of the “you'll regret it if” lines sound like your site, that is your answer.

  • A

    Native WP

    Pick it if longevity and looking native matter more than looking expensive, and you want the smallest stylesheet to keep.

    You'll regret it ifthe plugin has to sell itself with screenshots.

  • B

    Premium Command Deck

    Pick it if the plugin should feel like a paid product, you can afford the largest stylesheet, and dark mode is worth having.

    You'll regret it ifyour users run a light admin colour scheme and the dark sidebar fights it.

  • C

    Dense Utility

    Pick it if your users are power users on large sites who would rather type a setting name than scroll to find it.

    You'll regret it ifmost people who open the plugin open it once a year.

What happens after you choose

The content is already built and already identical across the three. All eight screens, all the copy, the fictional data, the 246-field inventory and every interaction — conditional fields, the CDN repeater, the dirty-and-save cycle, the ⌘K index, the four demo states — exist once and are shared.

Choosing a direction is therefore not a rewrite. It is porting one set of tokens and a handful of layout decisions: a sidebar or nav-tabs, the radius scale, the type stack, the density, the dark-mode rule. The other two stay on disk as reference, so changing your mind later costs a token file rather than a rebuild.
